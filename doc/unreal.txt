1. Introduction                                          *unreal-introduction*

                                                                 *unreal.nvim*

**unreal.nvim** helps working on Unreal Engine C++ projects: source/header
switching, clangd compilation-database generation, `UFUNCTION`/`UCLASS` macro
attribute completion, function implementation stubbing, an Unreal-aware
treesitter grammar, and optional extensions.


  **Warning:** this plugin is a work in progress. Commands, config options, and
  behavior may change without notice.

FEATURES                                        *unreal-introduction-features*

- Switch between header and source
- Generate function implementation stubs from a header declaration
- Rebuild the clangd compilation database
- Complete `UCLASS`/`USTRUCT`/`UFUNCTION`/`UPROPERTY` macro attributes
- Find/grep source, `.ini` and `Build.cs`/`Target.cs` files
- Open the `.uproject` in the Unreal editor
- Edit the `.uproject` in a buffer
- Finds installed engines and picks the one each `.uproject` asks for
- Optional extensions, e.g. telescope integration
- Unreal-aware treesitter grammar


ACKNOWLEDGEMENTS                        *unreal-introduction-acknowledgements*

The custom Unreal C++ treesitter grammar is tree-sitter-unreal-cpp
<https://github.com/taku25/tree-sitter-unreal-cpp> by taku25
<https://github.com/taku25>.

2. Installation                                          *unreal-installation*


REQUIREMENTS                                *unreal-installation-requirements*

- Neovim >= 0.12
- nvim-treesitter <https://github.com/nvim-treesitter/nvim-treesitter>
- plenary.nvim <https://github.com/nvim-lua/plenary.nvim>
- `rg` and `clangd` on `$PATH`
- clangd enabled with `vim.lsp` (see |unreal-installation-clangd|)
- An installed Unreal Engine build

Use the nvim-treesitter `main` branch; `master` is not supported.

`dotnet` prioritizes the bundled executable from the engine, then the one from
`$PATH`, so you usually don’t need to install it. See |unreal-engine-path|.

|unreal-extensions| are optional and may need other plugins.


LAZY.NVIM                                      *unreal-installation-lazy.nvim*

>lua
    {
        "lckdG/unreal.nvim",
        dependencies = {
            { "nvim-treesitter/nvim-treesitter", branch = "main" },
            "nvim-lua/plenary.nvim",
        },
        opts = {},
    }
<

Or call `setup()` yourself:

>lua
    require('unreal').setup({})
<


CLANGD                                            *unreal-installation-clangd*

Configure and enable clangd with `vim.lsp`:

>lua
    vim.lsp.config("clangd", {
        cmd = { "clangd" },
        filetypes = { "c", "cpp" },
        root_markers = { "compile_commands.json", ".git" },
    })
    vim.lsp.enable("clangd")
<


TREE-SITTER GRAMMAR                  *unreal-installation-tree-sitter-grammar*

After installing, run `:TSUpdate cpp` once so nvim-treesitter builds the Unreal
C++ grammar.

The plugin replaces nvim-treesitter’s `cpp` parser with
tree-sitter-unreal-cpp <https://github.com/taku25/tree-sitter-unreal-cpp>. This
applies to every C++ file, not only Unreal projects, and there is no opt-out:
Code Impl |unreal-commands-code| and Code Macro |unreal-commands-code| depend
on it.

3. Config                                                      *unreal-config*

All options are optional. Defaults:

>lua
    require('unreal').setup({
        custom_treesitter = {
            url = 'https://github.com/taku25/tree-sitter-unreal-cpp',
            revision = '2d2d5c19a9a83e432e43c041252106995614b29a',
        },
        command_lead = "Unreal",
        cmd_abbreviations = {},
        clangd_build_args = { "-NoExecCodeGenActions" },
        extensions = {},
    })
<


CUSTOM_TREESITTER                            *unreal-config-custom_treesitter*

Grammar registered as nvim-treesitter’s `cpp` parser. Override `url` and
`revision` to pin another build of the grammar.


COMMAND_LEAD                                      *unreal-config-command_lead*

Name of the user command. With `command_lead = "UE"` the commands become `:UE
Project Open`, `:UE Build Clangd`, …


CMD_ABBREVIATIONS                            *unreal-config-cmd_abbreviations*

Command-line abbreviations, expanded to `<command_lead> <value>`:

>lua
    cmd_abbreviations = { uo = "Project Open", uc = "Build Clangd" }
<


CLANGD_BUILD_ARGS                            *unreal-config-clangd_build_args*

Extra arguments for the UnrealBuildTool `-mode=GenerateClangDatabase` call made
by Build Clangd |unreal-commands-build|. Each entry is one argument.


EXTENSIONS                                          *unreal-config-extensions*

Optional integrations, keyed by name. A table enables the extension with those
options, `true` enables it with none, `false` disables it. Unknown names show
an error. See |unreal-extensions|.

>lua
    extensions = {
        telescope = { ignores = { "%.uasset" } },
    }
<


TELESCOPE_EXTENDED_IGNORES          *unreal-config-telescope_extended_ignores*

Deprecated, removed in 0.3.0. Use `extensions = { telescope = { ignores = ... }
}` instead.

Still accepted for now: it shows a deprecation warning and becomes
`extensions.telescope.ignores`, which enables the extension. It is ignored if
`ignores` is already set there, or if the extension is set to `false`.

4. Extensions                                              *unreal-extensions*

Extensions are optional integrations, enabled through the `extensions` option
in |unreal-config|. Nothing is enabled by default.


TELESCOPE                                        *unreal-extensions-telescope*

Runs pickers and searches through telescope.nvim
<https://github.com/nvim-telescope/telescope.nvim>:

- Search Files |unreal-commands-search| and Search Grep |unreal-commands-search| become live telescope pickers
- uproject and macro choices open in a telescope picker; Code Macro |unreal-commands-code| previews the macro documentation

>lua
    require('unreal').setup({
        extensions = {
            telescope = {
                ignores = { "%.uasset", "%.umap" },
            },
        },
    })
<

`telescope = true` enables it with no options.

`ignores` are Lua patterns appended to telescope’s global
`file_ignore_patterns`, so they apply to every telescope picker, not only
Search Files / Search Grep. There are no default patterns.

If telescope.nvim is not installed, an error is shown and the built-in UI is
kept.


CUSTOM UI PROVIDER                      *unreal-extensions-custom-ui-provider*

All prompts, pickers and searches go through `require('unreal.ui')`. Without an
extension it uses `vim.ui.select`, `vim.ui.input` and the quickfix list, so
plugins that replace `vim.ui` (dressing.nvim, snacks.nvim) apply.

To plug in another picker, pass a provider to `Use()` after `setup()`. It must
implement all four functions:

>lua
    require('unreal.ui').Use({
        -- items: { name = string, value = any, desc = string[] | "" }
        -- call cb with the chosen item, or nil when cancelled
        Select = function(items, opts, cb) end,
        -- same signature as vim.ui.input
        Input = function(opts, cb) end,
        -- cmd: { "rg", "--files", <scope args...> }
        FileSearch = function(cmd, opts) end,
        -- cmd: { "rg", "--vimgrep", "-S", <scope args...> }, without the search pattern
        GrepSearch = function(cmd, opts) end,
    })
<

`<scope args...>` can be several args, e.g. `--no-ignore -g !Intermediate/ -g
*.ini`; the last one is always the file name glob. Use `cmd` as given; do not
assume it ends with `-g <glob>` only.

`opts.prompt` holds the prompt or picker title. `desc` holds documentation
lines for Code Macro |unreal-commands-code| items and is `""` otherwise.
`Use(nil)` restores the built-in UI.

5. Commands                                                  *unreal-commands*

                                                                     *:Unreal*

All commands are `:Unreal <Group> <Action>` (see |unreal-config-command_lead|),
with `<Tab>` completion for both words. If several `.uproject` files are found,
the first command that needs one asks you to choose, and the choice is kept for
the session (see |unreal-engine-path|).


ENGINE                                                *unreal-commands-engine*


ENGINE SETPATH ~

                                                      *:Unreal-Engine-SetPath*

Prompt for an engine folder and use it for every command instead of the engine
the `.uproject` asks for. It is kept until `Engine ClearPath`, a `:cd` to
another project, or Neovim closes; it is not saved to disk. See
|unreal-engine-path|.


ENGINE CLEARPATH ~

                                                    *:Unreal-Engine-ClearPath*

Forget the folder set with `Engine SetPath`, so commands go back to the engine
the `.uproject` asks for.


PROJECT                                              *unreal-commands-project*


PROJECT OPEN ~

                                                        *:Unreal-Project-Open*

Open the project’s `.uproject` in the Unreal editor, using the engine the
`.uproject` asks for. The editor runs in the background and keeps running if
Neovim closes.


PROJECT EDIT ~

                                                        *:Unreal-Project-Edit*

Open the project’s `.uproject` in a buffer. No engine needed. `.uproject` and
`.uplugin` files open as `json`, indented with tabs (4 wide) like Unreal writes
them.


PROJECT SELECT ~

                                                      *:Unreal-Project-Select*

Choose which `.uproject` the other commands use. Only needed when the project
folder has several; with one, it is picked automatically.


BUILD                                                  *unreal-commands-build*


BUILD CLANGD ~

                                                        *:Unreal-Build-Clangd*

Regenerate `compile_commands.json` with UnrealBuildTool and copy it next to the
`.uproject`. Only `dotnet` and UnrealBuildTool are needed, not the editor, so
it also works on a source build before the editor is compiled. UnrealBuildTool
runs with the engine’s bundled `dotnet` when there is one, otherwise with the
one from `$PATH` (see |unreal-engine-path|). Output is shown in a terminal
split; press any key to close it when the build is done.


CODE                                                    *unreal-commands-code*


CODE IMPL ~

                                                           *:Unreal-Code-Impl*

With the cursor on a function declaration in a header, append an implementation
stub to the matching `.cpp`, or jump to it if it exists.

- `BlueprintNativeEvent` and RPC functions: `_Implementation` stub
- `WithValidation`: also a `_Validate` stub
- `BlueprintImplementableEvent`: no stub
- Pure virtual, deleted and inline functions: no stub


CODE MACRO ~

                                                          *:Unreal-Code-Macro*

Complete a `UCLASS`/`USTRUCT`/`UFUNCTION`/`UPROPERTY` specifier under the
cursor. Requires clangd.


CODE SWITCHSOURCEHEADER ~

                                             *:Unreal-Code-SwitchSourceHeader*

Switch between a header and its source file. Looks in the module’s
`Public`/`Private` folders first; if nothing matches, asks clangd.


SEARCH                                                *unreal-commands-search*


SEARCH FILES ~

                                                        *:Unreal-Search-Files*

Find files with `rg`. Asks for the file type first (scopes are listed below),
then:

- built-in UI: asks for part of the file name, runs the search once and fills the quickfix list
- with an extension |unreal-extensions| such as Telescope: opens its live file search


SEARCH GREP ~

                                                         *:Unreal-Search-Grep*

Grep files with `rg`. Asks for the file type first (scopes are listed below),
then:

- built-in UI: asks for the pattern, runs the search once and fills the quickfix list
- with an extension |unreal-extensions| such as Telescope: opens its live grep


SEARCH SCOPES ~

  -----------------------------------------------------------------------
  Scope                               Files
  ----------------------------------- -----------------------------------
  All                                 *.h, *.cpp

  Headers                             *.h

  Cpp                                 *.cpp

  Ini                                 *.ini, including gitignored ones
                                      such as Saved/Config/; skips
                                      Intermediate/, Binaries/ and
                                      CrashReportClient/

  Build Files                         *.Build.cs, *.Target.cs
  -----------------------------------------------------------------------
With the built-in UI, the typed name only matches the part before the
extension. For Build Files that is the module or target name: `Editor` finds
`GameEditor.Target.cs`, `Target` finds nothing.


DEPRECATED NAMES                            *unreal-commands-deprecated-names*

The old one-word commands still work until 0.3.0, with a deprecation warning:

  Old                  New
  -------------------- -------------------------
  SetEnginePath        Engine SetPath
  OpenProject          Project Open
  RebuildClangd        Build Clangd
  CreateImpl           Code Impl
  CompleteMacro        Code Macro
  SwitchSourceHeader   Code SwitchSourceHeader
  FindSource           Search Files
  GrepSource           Search Grep

6. Engine path                                            *unreal-engine-path*

When Neovim starts, the plugin reads which Unreal Engine versions are
installed:

  -------------------------------------------------------------------------------------------------------------------
  OS                                  Source
  ----------------------------------- -------------------------------------------------------------------------------
  Windows                             %ProgramData%\Epic\UnrealEngineLauncher\LauncherInstalled.dat (launcher) and
                                      the registry key HKCU\Software\Epic Games\Unreal Engine\Builds (source builds)

  Mac                                 ~/Library/Application Support/Epic/UnrealEngineLauncher/LauncherInstalled.dat

  Linux                               ~/.config/Epic/UnrealEngine/Install.ini
  -------------------------------------------------------------------------------------------------------------------
An engine folder is only used when it has
`Engine/Binaries/DotNET/UnrealBuildTool/UnrealBuildTool.dll` and a usable
`dotnet`.

`dotnet` prioritizes the bundled executable from the engine
(`Engine/Binaries/ThirdParty/DotNet/<version>/<os>-<arch>/`, newest version
first), then the one from `$PATH`.

Commands that need the engine pick it in this order:

1. the folder set with `:Unreal Engine SetPath`
2. the installed engine named by the `.uproject`’s `EngineAssociation` field: a version such as `"5.4"` (the launcher lists it as `UE_5.4`) or the ID of a source build
3. otherwise they ask for the engine folder; the answer is used once and not remembered

`Project Open` also needs the engine’s `UnrealEditor` program. `Build Clangd`
only needs `dotnet` and UnrealBuildTool.

The project folder is the closest one above the working directory that has a
`.uproject`. If there is none, the closest one with `.git` or `.p4ignore` is
used, and finally the working directory itself. `.uproject` files are searched
under it (at most 20). The chosen `.uproject` and the `Engine SetPath` folder
are kept until Neovim closes or the working directory moves to another project
folder. Nothing is saved to disk.

7. Health                                                      *unreal-health*

Run `:checkhealth unreal` to check:

- `rg` and `clangd` are installed
- plenary.nvim is installed
- telescope.nvim is available, only when the telescope extension |unreal-extensions-telescope| is enabled
- clangd is enabled with `vim.lsp.enable("clangd")`
- `setup()` was called
- a `.uproject` is chosen for this session (run any project command, or `:Unreal Project Select`)
- the engine for it is found: the folder from `Engine SetPath` (shown as a warning, since it overrides the `.uproject`), or the installed engine named by its `EngineAssociation`
- the engine’s editor, `dotnet` and UnrealBuildTool are found, with the path of each; for `dotnet` it also tells whether it is the engine’s bundled one or the one from `$PATH`
