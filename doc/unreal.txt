1. Introduction                                          *unreal-introduction*

                                                                 *unreal.nvim*

**unreal.nvim** helps working on Unreal Engine C++ projects: source/header
switching, clangd compilation-database generation, `UFUNCTION`/`UCLASS` macro
attribute completion, function implementation stubbing, an Unreal-aware
treesitter grammar, and optional extensions.


  **Warning:** this plugin is a work in progress. Commands, config options, and
  behavior may change without notice.

FEATURES                                        *unreal-introduction-features*

- Switch between header and source
- Generate function implementation stubs from a header declaration
- Rebuild the clangd compilation database
- Complete `UCLASS`/`USTRUCT`/`UFUNCTION`/`UPROPERTY` macro attributes
- Find/grep source, `.ini` and `Build.cs`/`Target.cs` files
- Open the `.uproject` in the Unreal editor
- Edit the `.uproject` in a buffer
- Finds installed engines and picks the one each `.uproject` asks for
- Optional extensions, e.g. telescope integration
- Unreal-aware treesitter grammar


ACKNOWLEDGEMENTS                        *unreal-introduction-acknowledgements*

The custom Unreal C++ treesitter grammar is tree-sitter-unreal-cpp
<https://github.com/taku25/tree-sitter-unreal-cpp> by taku25
<https://github.com/taku25>.


==============================================================================
2. Installation                                          *unreal-installation*


REQUIREMENTS                                *unreal-installation-requirements*

- Neovim >= 0.12
- nvim-treesitter <https://github.com/nvim-treesitter/nvim-treesitter>
- plenary.nvim <https://github.com/nvim-lua/plenary.nvim>
- `rg` and `clangd` on `$PATH`
- clangd enabled with `vim.lsp` (see |unreal-installation-clangd|)
- An installed Unreal Engine build

Use the nvim-treesitter `main` branch; `master` is not supported.

|unreal-extensions| are optional and may need other plugins.


LAZY.NVIM                                      *unreal-installation-lazy.nvim*

>lua
    {
        "lckdG/unreal.nvim",
        dependencies = {
            { "nvim-treesitter/nvim-treesitter", branch = "main" },
            "nvim-lua/plenary.nvim",
        },
        opts = {},
    }
<

Or call `setup()` yourself:

>lua
    require('unreal').setup({})
<


CLANGD                                            *unreal-installation-clangd*

Configure and enable clangd with `vim.lsp`:

>lua
    vim.lsp.config("clangd", {
        cmd = { "clangd" },
        filetypes = { "c", "cpp" },
        root_markers = { "compile_commands.json", ".git" },
    })
    vim.lsp.enable("clangd")
<


TREE-SITTER GRAMMAR                  *unreal-installation-tree-sitter-grammar*

After installing, run `:TSUpdate cpp` once so nvim-treesitter builds the Unreal
C++ grammar.

The plugin replaces nvim-treesitter’s `cpp` parser with
tree-sitter-unreal-cpp <https://github.com/taku25/tree-sitter-unreal-cpp>. This
applies to every C++ file, not only Unreal projects, and there is no opt-out:
Code Impl |unreal-commands-code| and Code Macro |unreal-commands-code| depend
on it.

3. Config                                                      *unreal-config*

All options are optional. Defaults:

>lua
    require('unreal').setup({
        custom_treesitter = {
            url = 'https://github.com/taku25/tree-sitter-unreal-cpp',
            revision = '2d2d5c19a9a83e432e43c041252106995614b29a',
        },
        engine_source = {
            git_url = 'https://github.com/EpicGames/UnrealEngine',
            clone_dir = nil,
        },
        command_lead = "Unreal",
        uproject_limits = 5,
        cmd_abbreviations = {},
        clangd_build_args = { "-NoExecCodeGenActions" },
        extensions = {},
    })
<


CUSTOM_TREESITTER                            *unreal-config-custom_treesitter*

Grammar registered as nvim-treesitter’s `cpp` parser. Override `url` and
`revision` to pin another build of the grammar.


ENGINE_SOURCE                                    *unreal-config-engine_source*

Where Engine Checkout |unreal-commands-engine| gets engine source code, and
where `Engine Build` looks for checkouts to build. `git_url` is the repository
whose tags are listed and cloned. `clone_dir` is an existing folder that
receives one subfolder per cloned tag; it has no default, so `Engine Checkout`
shows an error until you set it. `Engine Build` can still rebuild the
project’s engine or the `SetPath` folder without it.


COMMAND_LEAD                                      *unreal-config-command_lead*

Name of the user command. With `command_lead = "UE"` the commands become `:UE
Project Open`, `:UE Build Clangd`, …


UPROJECT_LIMITS                                *unreal-config-uproject_limits*

Most `.uproject` files a command looks for below the project folder. Raise it
if the picker misses projects.


CMD_ABBREVIATIONS                            *unreal-config-cmd_abbreviations*

Command-line abbreviations, expanded to `<command_lead> <value>`:

>lua
    cmd_abbreviations = { uo = "Project Open", uc = "Build Clangd" }
<


CLANGD_BUILD_ARGS                            *unreal-config-clangd_build_args*

Extra arguments for the UnrealBuildTool `-mode=GenerateClangDatabase` call made
by Build Clangd |unreal-commands-build|. Each entry is one argument.


EXTENSIONS                                          *unreal-config-extensions*

Optional integrations, keyed by name. A table enables the extension with those
options, `true` enables it with none, `false` disables it. Unknown names show
an error. See |unreal-extensions|.

>lua
    extensions = {
        telescope = { ignores = { "%.uasset" } },
    }
<


==============================================================================
4. Extensions                                              *unreal-extensions*

Extensions are optional integrations, enabled through the `extensions` option
in |unreal-config|. Nothing is enabled by default.


TELESCOPE                                        *unreal-extensions-telescope*

Runs pickers and searches through telescope.nvim
<https://github.com/nvim-telescope/telescope.nvim>:

- Search Files |unreal-commands-search| and Search Grep |unreal-commands-search| become live telescope pickers
- uproject and macro choices open in a telescope picker; Code Macro |unreal-commands-code| previews the macro documentation

>lua
    require('unreal').setup({
        extensions = {
            telescope = {
                ignores = { "%.uasset", "%.umap" },
            },
        },
    })
<

`telescope = true` enables it with no options.

`ignores` are Lua patterns appended to telescope’s global
`file_ignore_patterns`, so they apply to every telescope picker, not only
Search Files / Search Grep. There are no default patterns.

If telescope.nvim is not installed, an error is shown and the built-in UI is
kept.


CUSTOM UI PROVIDER                      *unreal-extensions-custom-ui-provider*

All prompts, pickers and searches go through `require('unreal.ui')`. Without an
extension it uses `vim.ui.select`, `vim.ui.input` and the quickfix list, so
plugins that replace `vim.ui` (dressing.nvim, snacks.nvim) apply.

To plug in another picker, pass a provider to `Use()` after `setup()`. It must
implement all four functions:

>lua
    require('unreal.ui').Use({
        -- items: { name = string, value = any, desc = string[] | "" }
        -- call cb with the chosen item, or nil when cancelled
        Select = function(items, opts, cb) end,
        -- same signature as vim.ui.input
        Input = function(opts, cb) end,
        -- cmd: { "rg", "--files", <scope args...> }
        FileSearch = function(cmd, opts) end,
        -- cmd: { "rg", "--vimgrep", "-S", <scope args...> }, without the search pattern
        GrepSearch = function(cmd, opts) end,
    })
<

`<scope args...>` can be several args, e.g. `--no-ignore -g !Intermediate/ -g
*.ini`; the last one is always the file name glob. Use `cmd` as given; do not
assume it ends with `-g <glob>` only.

`opts.prompt` holds the prompt or picker title. `desc` holds documentation
lines for Code Macro |unreal-commands-code| items and is `""` otherwise.
`Use(nil)` restores the built-in UI.

5. Commands                                                  *unreal-commands*

                                                                     *:Unreal*

All commands are `:Unreal <Group> <Action>` (see |unreal-config-command_lead|),
with `<Tab>` completion for both words. See |unreal-engine-path| for how the
`.uproject` and engine are chosen.


ENGINE                                                *unreal-commands-engine*


ENGINE SETPATH ~

                                                      *:Unreal-Engine-SetPath*

Use an engine folder you type instead of the one the `.uproject` asks for.
Lasts until `Engine ClearPath`, `:cd` to another project, or Neovim closes.


ENGINE CLEARPATH ~

                                                    *:Unreal-Engine-ClearPath*

Forget the `Engine SetPath` folder.


ENGINE CHECKOUT ~

                                                     *:Unreal-Engine-Checkout*

Pick an engine release tag (newest first) from |unreal-config-engine_source|
`git_url` and clone it into `<clone_dir>/<tag>` in a terminal split. Only the
tag’s latest commit is downloaded (`git clone --depth 1`). Needs `git`, and
access to the repository: Epic’s repository is private until you link your
GitHub account to your Epic Games account. Shows an error if `clone_dir` is not
set or does not exist.


ENGINE BUILD ~

                                                        *:Unreal-Engine-Build*

Build the Unreal editor from engine source code. The picker lists, in this
order:

1. the engine of the chosen `.uproject`, found in the same order as other commands use (see |unreal-engine-path|: the `SetPath` folder, its `EngineAssociation`, or the native engine), with its version.
2. the `Engine SetPath` folder, with its version.
3. every checkout under `<clone_dir>` made by `Engine Checkout`, by folder name.

The first two are only listed when that engine was built from source: a
launcher engine has no build scripts. The same folder can show up more than
once, for example while `SetPath` is set (it is then both entries) or points at
a checkout; every entry builds the same folder.

Only folders that have the `Setup`, `GenerateProjectFiles` and `Build` scripts
are listed. Pick one, confirm, and the build runs in a terminal split from that
folder. A build can take hours and tens of GB of disk. The steps run one after
another and stop at the first one that fails:

1. `Setup.sh` / `Setup.bat`: downloads the engine’s binary dependencies and installs prerequisites. It may ask for system packages or admin rights.
2. `GenerateProjectFiles.sh` / `.bat`: writes the project files the build tools need.
3. Build the `UnrealEditor` target in the `Development` configuration (optimized, with editor tools; the usual choice).

The build step per platform:

>sh
    # Linux
    Engine/Build/BatchFiles/Linux/Build.sh UnrealEditor Linux Development
    # Mac
    Engine/Build/BatchFiles/Mac/Build.sh UnrealEditor Mac Development
    # Windows
    Engine\Build\BatchFiles\Build.bat UnrealEditor Win64 Development -WaitMutex
<

Shows an error with the exit code if a step fails, an error if `clone_dir` does
not exist, and a warning if there is nothing to build. `clone_dir` is optional
here: without it, only the project’s engine and the `SetPath` folder are
offered.


PROJECT                                              *unreal-commands-project*


PROJECT OPEN ~

                                                        *:Unreal-Project-Open*

Open the project in the Unreal editor. The editor keeps running if Neovim
closes.


PROJECT EDIT ~

                                                        *:Unreal-Project-Edit*

Open the `.uproject` in a buffer. `.uproject` and `.uplugin` files open as
`json` with 4-wide tabs.


PROJECT SELECT ~

                                                      *:Unreal-Project-Select*

Choose which `.uproject` the other commands use, e.g. when the project folder
has several.


PROJECT LOG ~

                                                         *:Unreal-Project-Log*

Pick a log from `Saved/Logs` in the project folder, newest first, and open it
in a new tab at the last line. A log that is already open is reloaded first, so
new lines show.


BUILD                                                  *unreal-commands-build*


BUILD CLANGD ~

                                                        *:Unreal-Build-Clangd*

Regenerate `compile_commands.json` with UnrealBuildTool and copy it next to the
`.uproject`. Does not need the editor. Output shows in a terminal split; press
any key to close it when done. If it fails, shows an error with the exit code,
puts the compiler errors (file, line, message) in the quickfix list and opens
it. Warnings are left out. No compiler errors found: the quickfix list is left
as it was; read the terminal output.


BUILD CONFIG ~

                                                        *:Unreal-Build-Config*

Pick a `BuildConfiguration.xml` (UnrealBuildTool settings) and open it:

  ----------------------------------------------------------------------------------------------------
  Entry                               File
  ----------------------------------- ----------------------------------------------------------------
  Project Config                      <project>/Saved/UnrealBuildTool/BuildConfiguration.xml

  User Config                         ~/.config/Unreal Engine/UnrealBuildTool/BuildConfiguration.xml
                                      (Linux, Mac)

  User AppData / Document Config      %APPDATA%\Unreal Engine\UnrealBuildTool\… and
                                      Documents\Unreal Engine\UnrealBuildTool\… (Windows)

  Engine Config                       <engine>/Engine/Saved/UnrealBuildTool/BuildConfiguration.xml
  ----------------------------------------------------------------------------------------------------
Project and Engine entries need a chosen `.uproject`. A missing file is created
from a template after you confirm, and written when you save.


BUILD EDITOR ~

                                                        *:Unreal-Build-Editor*

Compile the project’s C++ code so the Unreal editor can open it, without the
editor or an IDE. Builds the `<Project>Editor` target (the project plus its
editor code) in the `Development` configuration with UnrealBuildTool:

>sh
    RunUBT.sh <Project>Editor <Platform> Development -project=<uproject> -WaitMutex
<

Output shows in a terminal split that follows the end of the output.
`-WaitMutex` makes the build wait instead of failing when another
UnrealBuildTool build (for example from the editor) is already running.

If the build fails, shows an error with the exit code, puts the compiler errors
(file, line, message) in the quickfix list and opens it. Warnings are left out.
No compiler errors found (e.g. the failure was not in C++ code): the quickfix
list is left as it was; read the terminal output.


BUILD CLEANEDITOR ~

                                                   *:Unreal-Build-CleanEditor*

Like `Build Editor`, but deletes the project’s previous build output first
and then compiles everything again. Use it when an incremental build behaves
oddly, for example after moving files, changing `.Build.cs` modules or
switching engine versions. Slower than `Build Editor`, because nothing is
reused. UnrealBuildTool does both steps in one run:

>sh
    RunUBT.sh <Project>Editor <Platform> Development -project=<uproject> -Rebuild -WaitMutex
<

Output, `-WaitMutex` and errors work as in `Build Editor`: if the clean or the
build fails, shows an error with the exit code, puts the compiler errors in the
quickfix list and opens it.


CODE                                                    *unreal-commands-code*


CODE IMPL ~

                                                           *:Unreal-Code-Impl*

With the cursor on a function declaration in a header, append an implementation
stub to the matching `.cpp`, or jump to it if it exists.

- `BlueprintNativeEvent` and RPC functions: `_Implementation` stub
- `WithValidation`: also a `_Validate` stub
- `BlueprintImplementableEvent`: no stub
- Pure virtual, deleted and inline functions: no stub


CODE MACRO ~

                                                          *:Unreal-Code-Macro*

Complete a `UCLASS`/`USTRUCT`/`UFUNCTION`/`UPROPERTY` specifier under the
cursor. Requires clangd.


CODE SWITCHSOURCEHEADER ~

                                             *:Unreal-Code-SwitchSourceHeader*

Switch between a header and its source file. Looks in the module’s
`Public`/`Private` folders first; if nothing matches, asks clangd.


SEARCH                                                *unreal-commands-search*


SEARCH FILES ~

                                                        *:Unreal-Search-Files*

Find files with `rg`. Asks for the file type first (scopes are listed below),
then:

- built-in UI: asks for part of the file name, runs the search once and fills the quickfix list
- with an extension |unreal-extensions| such as Telescope: opens its live file search


SEARCH GREP ~

                                                         *:Unreal-Search-Grep*

Grep files with `rg`. Asks for the file type first (scopes are listed below),
then:

- built-in UI: asks for the pattern, runs the search once and fills the quickfix list
- with an extension |unreal-extensions| such as Telescope: opens its live grep


SEARCH SCOPES ~

  -----------------------------------------------------------------------
  Scope                               Files
  ----------------------------------- -----------------------------------
  All                                 *.h, *.cpp

  Headers                             *.h

  Cpp                                 *.cpp

  Ini                                 *.ini, including gitignored ones
                                      such as Saved/Config/; skips
                                      Intermediate/, Binaries/ and
                                      CrashReportClient/

  Build Files                         *.Build.cs, *.Target.cs
  -----------------------------------------------------------------------
With the built-in UI, the typed name only matches the part before the
extension. For Build Files that is the module or target name: `Editor` finds
`GameEditor.Target.cs`, `Target` finds nothing.

6. Engine path                                            *unreal-engine-path*

Installed engines are read when Neovim starts:

  -------------------------------------------------------------------------------------------------------------------
  OS                                  Source
  ----------------------------------- -------------------------------------------------------------------------------
  Windows                             %ProgramData%\Epic\UnrealEngineLauncher\LauncherInstalled.dat and registry
                                      HKCU\Software\Epic Games\Unreal Engine\Builds (source builds)

  Mac                                 ~/Library/Application Support/Epic/UnrealEngineLauncher/LauncherInstalled.dat

  Linux                               ~/.config/Epic/UnrealEngine/Install.ini
  -------------------------------------------------------------------------------------------------------------------
An engine folder is accepted when it has a readable
`Engine/Build/Build.version`. Each command then checks what it needs:

- `Build Clangd` needs `Engine/Build/BatchFiles/RunUBT.sh` (`RunUBT.bat` on Windows), the engine’s script that runs UnrealBuildTool. The script sets up the engine’s `dotnet` and builds UnrealBuildTool when needed.
- `Project Open` needs the editor.

Commands use, in order:

1. the folder from `:Unreal Engine SetPath`
2. the engine named by the `.uproject`’s `EngineAssociation` (e.g. `"5.4"` or a source build ID)
3. the native engine: when Neovim’s working directory is inside an engine source tree, and the `.uproject` is in a folder listed by that engine’s `.uprojectdirs` files (e.g. `Default.uprojectdirs`)
4. a prompt for the engine folder (not remembered)


ENGINE FROM SOURCE                     *unreal-engine-path-engine-from-source*

No installed engine, or you need a version the launcher does not offer: build
one from Epic’s source code.

1. Set |unreal-config-engine_source| `clone_dir` to an existing folder. Each checkout gets its own subfolder, e.g. `<clone_dir>/5.4.4-release`.
2. `:Unreal Engine Checkout`: pick a release tag; only its latest commit is cloned. Epic’s repository is private: link your GitHub account to your Epic Games account first, and make sure `git` can log in to GitHub (SSH key or credential helper).
3. `:Unreal Engine Build`: pick the checkout (or the project’s engine or `SetPath` folder, if it was built from source) and confirm. Setup, project file generation and the editor build run in a terminal split; expect hours and tens of GB of disk.

The plugin does not register the built engine itself; it re-reads the installed
engines when the build succeeds. If the new engine is still not found, point to
it with `:Unreal Engine SetPath`.


PROJECT FOLDER                             *unreal-engine-path-project-folder*

The closest folder above the working directory with a `.uproject`, else with
`.git` or `.p4ignore`, else the working directory.

At startup and after `:cd` to another project, a `.uproject` directly in that
folder is chosen (one is picked if there are several). If there is none, the
first command that needs one searches subfolders (up to
|unreal-config-uproject_limits|) and asks if it finds several.

The chosen `.uproject` and the `SetPath` folder last until Neovim closes or you
`:cd` to another project. Nothing is saved to disk.

7. Health                                                      *unreal-health*

Run `:checkhealth unreal` to check:

- `rg` and `clangd` are installed
- plenary.nvim is installed
- telescope.nvim is available, only when the telescope extension |unreal-extensions-telescope| is enabled
- clangd is enabled with `vim.lsp.enable("clangd")`
- `setup()` was called
- the chosen `.uproject`
- its engine, found in the same order as the commands use (a `SetPath` folder shows as a warning), and the engine version
- the engine type:
    - `launcher-installed`: listed by the Epic Games Launcher
    - `source build, native engine`: the project sits inside the engine, in a folder listed by its `.uprojectdirs` files
    - `source build, cloned into configured clone dir`: a checkout directly inside |unreal-config-engine_source| `clone_dir`
    - `source build`: any other source build registered on this machine (`Install.ini` on Linux, the registry on Windows)
    - `unknown`: a `SetPath` folder none of the above knows about (shown as info)
- the engine’s editor and its `RunUBT` script (UnrealBuildTool); for a launcher engine, the advice is to verify it in the launcher
- for source builds, the `Setup`, `GenerateProjectFiles` and `Build` scripts that `Engine Build` runs
- |unreal-config-engine_source| `clone_dir` exists (only shown as info when not set) and `git` is installed, for `Engine Checkout` and `Engine Build`

Each problem comes with advice on how to fix it.
